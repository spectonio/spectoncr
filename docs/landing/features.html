Full Feature List

SpectonCR is a highly available OCI/Docker container registry written in Rust. Every service is stateless and horizontally scalable, storage is pluggable across filesystem, S3, GCS and Azure Blob, and images are replicated across regions with circuit-breaker-protected failover. This page is the complete inventory — what ships today, what it is configured with, and what is still landing.

What’s New — September 2026

Shipped today

The most recent work landed on main. Each item links to the pull request it shipped in.

📦 Multi-GB layers now push reliably — multipart blob uploads New

Pushing an image with a very large layer (a PyTorch-class image, for example) could fail at the end of the blob upload with a bare 500, while small images pushed fine. The blob was written with a single PUT, and object_store bounds one request end to end with its 180-second retry timeout — a layer that cannot reach the bucket inside that window times out, is retried, and exhausts the budget identically on every attempt, so retrying the push never helped.

Blobs above storage.multipart_threshold_mb are now written as a multipart upload. Every part gets its own request and its own retry budget, so object size is no longer bounded by a single request deadline. Payloads at or below the threshold take exactly the same single-PUT path as before, so manifests, tags and upload placeholders are untouched.

Pull request #35 Configuration & limits
⚙ Tunable storage retries & timeouts New
The S3 client’s retry and timeout behaviour was previously implicit defaults. It is now set explicitly from configuration and overridable with SPECTONCR_STORAGE_* environment variables, because Kubernetes deploys set env rather than mounting a --config file.
  • Max retries, retry deadline, connect and request timeouts
  • Multipart threshold, part size and part concurrency
  • Existing config files without the new keys deserialize unchanged
  • Shipped in #35
🛡 Safe multipart failure handling New
Operator-supplied tuning is clamped to what the backing store actually accepts, and a failed upload is aborted rather than left behind.
  • Part size raised to the 5 MiB floor S3 requires for non-final parts
  • Part size grown automatically when an object would exceed the 10,000-part cap
  • A bad config value degrades instead of failing every push
  • Failed uploads are aborted — no orphaned parts accruing storage charges
🚦 Per-tenant rate-limit env overrides
Blob HEAD storms during a push could hit the default per-tenant limit and return 429, with no way to tune it without a config file. The limits now take env overrides in both the registry and auth services.
  • SPECTONCR_RATE_LIMIT_DEFAULT_RPS — per tenant, default 100
  • SPECTONCR_RATE_LIMIT_IP_RPS — per IP, default 50
  • SPECTONCR_RATE_LIMIT_TOKEN_ISSUE_RPM — token issuance, default 60
  • Shipped in #32
🔌 Circuit breaker ignores NotFound
docker push and pull issue existence checks for objects that do not exist yet. Those were counted as storage failures and could trip the storage breaker open, after which real requests surfaced as 500 instead of 404.
  • Read ops classify NotFound as a healthy response, not a fault
  • CircuitBreaker::call_classified lets callers define failure
  • Absent manifests and blobs return a clean 404 again
  • Shipped in #21

Registry Core & OCI Distribution API

Stable

A full implementation of the OCI Distribution Specification, compatible with Docker, Podman, Buildah, containerd, and any OCI-compliant client. One Rust binary, no runtime dependencies.

📦 Image operations
  • Manifest push, pull and delete (v2 schema, manifest lists)
  • Chunked (PATCH) and monolithic blob uploads
  • Content-addressable blob storage keyed by digest
  • Tag listing, pagination and the /v2/_catalog API
  • Cross-repository blob mounting
🔗 Path models
  • Standard 2-segment Docker paths (org/image)
  • Multi-tenant 3-segment paths (tenant/project/image)
  • Default tenant applied automatically for 2-segment pushes
  • Works unchanged with docker, podman and containerd
⚡ Runtime
  • Rust + Axum + Tokio, fully async I/O
  • Single static binary, small memory footprint
  • Thousands of concurrent pulls per replica
  • Registry on :5000, auth on :5001

Large Layers & Blob Uploads

Updated Sept 2026

Machine-learning and data-science images routinely carry layers of a gigabyte or more. SpectonCR writes those blobs as multipart uploads so a single request deadline never caps object size.

🔁 Multipart write path
Applied at every blob write site in the registry — monolithic PUT, the PATCH-appended buffer, and upload completion.
  • Each part carries its own request and retry budget
  • Parts uploaded concurrently to keep a WAN link busy
  • Payloads at or below the threshold keep the original single-PUT path
  • Backend-agnostic: works on S3, MinIO, GCS, Azure and filesystem
🛠 Guard rails
  • 5 MiB minimum part size enforced for non-final parts
  • Part size grown when an object would need more than 10,000 parts
  • Aborted upload on failure, so no orphaned parts are billed
  • Unit tests plus S3 integration tests against MinIO
✅ Verified end to end
  • 180 MiB layer pushed through the real OCI endpoints into MinIO
  • Pulled back byte-identical on both MinIO and filesystem backends
  • No dangling multipart uploads left in the bucket
  • Small blobs and manifests confirmed on the unchanged path

High Availability & Resilience

Stable

Both services are stateless, so availability is a matter of running more replicas. What sits underneath is the part that matters: retries, breakers and failover that distinguish a real fault from ordinary traffic.

♻ Stateless scale-out
  • Registry and auth scale horizontally behind one service
  • HorizontalPodAutoscaler for both deployments
  • PodDisruptionBudgets and pod anti-affinity
  • No sticky sessions — any replica serves any request
🔌 Circuit breakers
  • Per-dependency breakers with configurable thresholds
  • Classified failures — NotFound counts as healthy
  • Half-open probing before a breaker closes again
  • Breaker state exported as metrics
🔄 Retries & timeouts
  • Exponential backoff with jitter
  • Explicit connect, request and retry deadlines
  • Per-part retry budgets on large uploads
  • Bounded so a slow dependency cannot queue indefinitely
🚦 Rate limiting
  • Per-tenant and per-IP request limits
  • Separate limit for token issuance
  • Env-overridable at runtime without a config file
  • Per-tenant quotas from the Tenant CRD
🩺 Health & readiness
  • /health endpoint for probes and load balancers
  • Region health loop with latency and failure counts
  • Automatic read failover to healthy regions
  • Health surfaced in the dashboard
💿 Data durability
  • Object storage durability for blobs and manifests
  • Async replication to secondary regions
  • Multipart uploads aborted cleanly on failure
  • Digest verification on write and on read

Multi-Region Replication

Stable

Manifests and blobs replicate across regions on an event-driven pipeline, with failover handled by the same resilience layer the storage path uses.

🌍 Replication engine
  • Async and semi-sync replication modes
  • Event-driven — a push enqueues replication work
  • Primary and secondary region roles
  • Backoff and retry on partitioned links
🛟 Failover
  • Health check loop per region
  • Reads served from the nearest healthy region
  • Circuit breaker isolates a failing region
  • Failover state visible in the dashboard and metrics
# Three-replica registry with multi-region enabled helm install spectoncr oci://ghcr.io/bwalia/charts/spectoncr \ --set registry.replicas=3 \ --set auth.replicas=2 \ --set multiRegion.enabled=true \ --set multiRegion.localRegion=us-east-1 \ --set multiRegion.isPrimary=true

🔍 Upstreams

  • Authenticated upstreams to avoid Docker Hub pull limits
  • Any additional OCI-compliant upstream by config

Authentication & Identity

Enterprise

Zero static credentials in production. Identity comes from your existing provider, and every token is short-lived and scoped.

🏢 SSO / OIDC
  • Authorization Code flow with PKCE
  • Azure AD / Entra ID, Okta, Google, any OIDC provider
  • Auto-provision users on first login
  • Group-to-role mapping, per tenant and per project
🤖 Machine identity
  • CI/CD OIDC federation: GitHub Actions, GitLab CI, Kubernetes SAs
  • Robot accounts with configurable expiry
  • API keys (nck_) with per-permission scoping
  • No static secrets in pipelines
🔑 Tokens
  • Docker-compatible token exchange at /auth/token
  • RS256 / EdDSA signed JWTs, JWKS published for verification
  • Short-lived by default (5–15 minutes)
  • Refresh tokens with instant revocation
📋 SCIM 2.0 provisioning
  • RFC 7644 Users and Groups endpoints
  • Pre-provision access before first login
  • Instant deprovisioning on offboarding
  • Group membership changes sync without a new login
🔐 Key management
  • HashiCorp Vault integration (Transit + KV)
  • Mounted PEM keypair or Vault-managed signing keys
  • Key rotation without downtime
  • Bootstrap admin for first-run setup only
🛡 Authorization
  • RBAC roles: Admin, Maintainer, Reader
  • AccessPolicy CRD with subjects, resources, actions, conditions
  • Scope-checked per repository operation
  • IP restrictions per tenant

Vulnerability Scanning & SBOM

Stable

Scanning is built into the registry, not bolted on. Every push is scanned in-process by specton-scanner — no Trivy daemon, no Grype shell-out, no external scanner pod.

🔎 SBOM extraction
  • OS packages: dpkg, apk, rpm
  • Language deps: npm, PyPI, Cargo, Go modules
  • ELF metadata fallback for un-packaged binaries
  • CycloneDX SBOM output, exportable to S3
📚 Vulnerability data
  • OSV as the bootstrap source
  • SpectonVulnDb: local Postgres mirror of OSV, GHSA and NVD
  • Ecosystem-aware matchers: apk, deb, rpm, semver, PEP 440, Go
  • Scheduled ingest via /admin/vulndb/ingest
⚖ Noise control & policy
  • CycloneDX VEX 1.4 ingestion (not_affected / fixed / under_investigation)
  • Suppressions with audit trail
  • Pass/fail policy gate with per-severity thresholds
  • Standalone policy evaluation endpoint
📡 Delivery
  • Results in Redis with a 1-hour TTL, keyed by digest
  • WebSocket progress stream for live UIs
  • Cross-image CVE search
  • Slack notifications and nightly PDF reports
